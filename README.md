# RIFTFALL — a reality-tear RNG for Roblox

You do not roll dice, coins or eggs here. You **tear rifts in reality**. Every tear
is a portal with a rarity, a colour, a sound and an income. Rare tears are visible
across the whole server, and the top tiers bend the sky.

- 25 rifts across 8 tiers + a storm-exclusive pool, from `1 in 2.3` to `1 in 100,000,000`
- Server-authoritative rolls, cooldowns and upgrade costs (the client sends intent only)
- Personal plots that display your rarest rifts as glowing, particle-emitting portals
- Passive **Flux** income, three upgrades (Luck, Tempo, Auto-Tear) and duplicate stacking
- **Riftodex** collection index with five milestone rewards
- **Rift Storms** every few minutes: server-wide luck surge + storm-only rifts + sky FX
- Saving with session locking, autosave, shutdown flush and read-only fallback
- Three fixed-value products (two passes, one Flux bundle) with idempotent receipts
- First-run guide (3 steps), Rift Storm warning banner and a built-in sound set
- Fully responsive, code-built UI for PC and mobile — no imported art assets at all

## Quick start

```bash
py tools/gen_data.py          # macOS/Linux: python3 tools/gen_data.py
py tools/build_place.py
```

Then:

1. Open **`out/Riftfall.rbxlx`** in Roblox Studio (`File -> Open from File`).
2. `Game Settings -> Security -> Enable Studio Access to API Services` (only needed for saving).
3. Press **Play**.

The viewport is intentionally empty in edit mode. The plaza, plots, sky, lighting and
the server-best board are all generated by `WorldBuilder` when the server starts.

Optional polish: open `Lighting` properties and set **Technology = Future** for the
best bloom and shadows. The game renders in every lighting technology; this only
changes how good the neon and atmosphere look.

Controls: **R** or the big button to tear · **Q** Riftodex · **E** Rift Lab · **Esc** closes panels.
A new profile also gets a 3-step guide pointing at the tear button, the Rift Lab and
the Riftodex; it is saved on the profile, so it resumes where it stopped and never
reappears once finished.

## Tooling

```bash
py -m pip install luaparser          # one-time dependency of the validator
py tools/gen_data.py --check        # generated rarity module matches the CSVs
py tools/build_place.py --check     # place file matches src/
py tools/validate_place.py          # XML, script inventory, Lua syntax, requires, remotes
py tools/check_layout.py            # HUD/guide rectangles at 640x360, 1024x768, 1920x1080
py tools/test_persistence.py        # runs DataService against a fake DataStore
py tools/simulate_balance.py        # 800k-roll Monte Carlo, writes out/balance_report.md
```

`validate_place.py` is the gate: it parses every `.luau` file with a Lua parser,
checks that every embedded script matches its file, that every
`require(script.Parent.X)` resolves, and that every remote used is declared.
Run it after any edit and before rebuilding the place.

Rebuild order after changing code or data:

```bash
py tools/gen_data.py && py tools/build_place.py && py tools/validate_place.py
```

## Turning on monetization

`Config.Products` ships with `id = 0` placeholders — the UI shows `COMING SOON` and
no purchase is attempted. To go live:

1. Publish the place once (Creator Dashboard needs an experience).
2. Create two **Game Passes** (Rift Runner 99 R$, Omega Aura 149 R$) and one
   **Developer Product** (Flux Pack 29 R$, fixed Flux).
3. Paste the three ids into `src/ReplicatedStorage/Riftfall/Config.luau`.
4. Rebuild the place and re-publish.

Purchase rules implemented in `MonetizationService`:

- One `ProcessReceipt` handler; every grant is keyed by `PurchaseId` and recorded in
  the profile **before** the receipt is acknowledged, so a replayed receipt never
  grants twice.
- If the save fails, the grant is rolled back and the receipt returns
  `NotProcessedYet` so Roblox retries.
- Passes are re-checked with `UserOwnsGamePassAsync` on join and after purchase.
- No product, pass or purchase changes roll odds. Luck is bought with Flux only.

## Audio

All cues are **built-in client sounds** (`rbxasset://sounds/...`) listed in
`Config.Sounds`, so nothing can be moderated or pulled and no marketplace id is
needed. `Audio.luau` runs every cue through one bus: master volume from
`Config.Audio.MasterVolume`, two base tones re-pitched per event, and a `SFX ON/OFF`
button in the top-right that mutes the whole session (it lives in the HUD, so a
respawn keeps it). Each surface owns its own cue — the Riftodex and Rift Lab panels
sound on open and close, the reveal controller owns roll/charge/reveal/sting
(`Config.Audio.StingTier`, tier 4 and up), `StormFX` owns the storm itself. Gamepad motors get a short pulse on tear and reveal; platforms
without a motor just skip it. A cue that fails to load is dropped silently — audio
never blocks gameplay.

To re-voice the game, replace strings in `Config.Sounds` with `rbxassetid://...`
values, or set a cue to `""` to disable it. Storm timing lives in `Config.Storm`:
first storm at 60s, a 10s `INCOMING` warning banner, then every 210-330s.

## Data and safety

- One DataStore entry per player (`Riftfall_Data_v1`, key `Player_<UserId>`).
- Session lock with a 120s TTL; a second live server loads read-only instead of
  overwriting the first, and the player is told progress will not save.
- Sanitizing on load: numbers clamped, unknown rift ids dropped, best rift recomputed
  from owned rifts, purchase log capped at 50 ids.
- Autosave every 90s, save on leave, save on `BindToClose`.
- If DataStores are unavailable (Studio API access off) the game plays in
  memory-only mode with a notice.
